Privacy & data

Your active MRCC workspace stays in your browser.

This page describes the current v28.1 public application. MRCC is a static web app with browser-local Lab state and no MRCC application backend for patient data, Lab state, accounts, or billing.

Effective October 1, 2026No active billingBrowser-local workspace

What MRCC stores locally

The active application may use localStorage or sessionStorage for Lab state, Sequence Families Lab preferences, Parameter presets and comparisons, interface preferences, last-Lab continuity, and staged workspace behavior. This data remains in the browser unless you explicitly export it.

Workspace exports

When you choose Export backup, the browser creates a JSON file from the active allowlisted workspace keys. MRCC does not automatically upload that file. Keep user-created labels free of patient identifiers or other sensitive information.

Offline cache

The service worker caches core static application assets so the Labs can continue to load after a successful visit. Clearing site data in your browser can remove cached assets and browser-local workspace state.

Analytics and network activity

The current MRCC application does not include client-side analytics, advertising, or an MRCC application API that receives Lab state. The hosting provider may still process standard request and security metadata needed to serve the website, such as IP-derived network information, request timing, and user-agent details, under its own infrastructure practices.

Retired browser data

Older MRCC versions included course, study-session, case-pack, and Protocol Workspace features. v28.1 no longer uses the patient/protocol-image workflow; its old browser-local Protocol Workspace keys are cleared when the Sequence Families Lab initializes. Settings can still detect and clear older retired learning keys without affecting current Lab states, presets, comparisons, or display preferences.

Accounts, Premium, and payments

Premium purchasing is not active in v28.1. If accounts or payment processing are introduced later, MRCC will require authenticated server-side entitlement checks and this privacy notice will be updated before those production flows are enabled.

Do not enter patient-identifying information into MRCC. The product is designed for educational reasoning with generic or synthetic state, not for storing clinical records.
